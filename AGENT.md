# Агент проекта: Автономная Магний-Графитовая Батарея (Заполярье)

Этот файл содержит базу знаний и список ресурсов для поиска информации, схем и практического опыта по созданию самодельных долгоиграющих гальванических элементов (в частности, магний-графитовых батарей с деполяризаторами из диоксида марганца/пиролюзита).

## 🎯 Цель агента
Проектирование и расчет автономной радиостанции для Средних Волн (СВ, длина волны 100-200м) с питанием от земляной/солевой магний-графитовой батареи.

**Ключевые параметры проекта:**
*   **Конструкция источника питания:** Система из 3-х последовательно соединенных бочек (ПНД 65л) с магниевыми анодами (ПМ-5У) и графитовыми катодами в оболочке из диоксида марганца ("куклах").
*   **Условия эксплуатации:** Заполярье (жесткий минус, размещение бочек под землей, водяное заземление).
*   **Интервал обслуживания:** Строго не реже 1 раза в 14 месяцев (замена растворившихся магниевых анодов, чистка кукол от шлама, частичное обновление электролита).
*   **Рабочий режим:** Постоянная отдача мощности в эфир (5-15 Вт) с использованием выделяемого химического тепла и электрического самоподогрева для предотвращения замерзания ячеек зимой.

## 🧪 Ключевые термины для поиска и анализа

*   **Катодная "кукла":** Процесс обмотки графитового стержня (катода) тканью/холстом и плотной засыпки в этот зазор токопроводящей и деполяризующей смеси.
*   **Состав засыпки (Деполяризатор):** Смесь **Диоксида марганца (MnO2 / пиролюзит)** и токопроводящего наполнителя (чешуйчатый графит, толченый уголь, сажа). Марганцовка (KMnO4) растворима и сожжет магний — ее использовать нельзя!
*   **Электролит:** Хлорид кальция (CaCl2) — для морозостойкости. Хлорид аммония (NH4Cl) или хлорид магния (MgCl2) — для стабильности.
*   **Газовая поляризация:** Проблема выделения водорода на графите, из-за которой падает ток. Пиролюзит решает эту проблему, окисляя водород до воды.
*   **Шлам:** Осадок (гидроксид магния), образующийся при работе батареи, который может забить бочку и остановить реакцию. Поиск методов минимизации шлама.

## 📝 Задачи агента при работе с ресурсами
1. **Анализ состава "Куклы":** Выяснить оптимальное соотношение диоксида марганца и графитового порошка (обычно от 1:1 до 8:1 по массе).
2. **Выбор сепаратора:** Найти лучший материал для мешка (геотекстиль, брезент, стеклоткань), который не сгниет в солевом растворе за год и будет пропускать ионы, но удерживать порошок.
3. **Борьба со шламом:** Найти способы укладки магниевого анода, чтобы образующийся гидроксид магния легко осыпался на дно бочки и не замыкал электроды.

## 🚀 Деплой и Инфраструктура (MCP SSH)

Проект использует автоматизированный деплой через **GitHub Actions** и управляется на сервере с помощью MCP (Model Context Protocol) SSH-инструментов.

### 1. Маршрутизация и сервер
*   **Хост:** `at5.su` (подключение через MCP `user-ssh-alttechno-bitrix` на порту 4422, пользователь `bitrix`).
*   **Авторизация:** Осуществляется по приватному SSH-ключу. В GitHub Secrets репозитория добавлен ключ `ALTTECHNO`.
*   **Роутинг Bitrix:** Публичный доступ организован через ЧПУ-правила в `urlrewrite.php`. Публичный адрес: **`https://alttechno.ru/RadioVTV`** (есть алиас `/dvtv`). Эти правила перенаправляют запросы на физический файл `/local/presentations/power_system_zapolyarye/index.php`.

### 2. GitHub Actions (deploy.yml)
*   При пуше в ветку `main` срабатывает workflow `Deploy presentation`.
*   **Сборка:** Python-скрипт `.github/scripts/build_presentation.py` берёт исходный HTML (`power-system-zapolyarye-transmitter-guide.html`), оборачивает его в `prolog_before.php` (для работы внутри ядра 1С-Битрикс), меняет пути к картинкам на серверные абсолютные (`$presentationsAssetBase`) и генерирует готовый `index.php` в папку `deploy/`.
*   **Доставка (SCP):** Готовый `index.php` и локальные `.jpg` изображения заливаются по SSH на хост в директорию `/home/bitrix/www/local/presentations/power_system_zapolyarye/`. Эталонный файл правил `www/urlrewrite.php` также копируется на сервер, чтобы не потерять настройки роутинга.

### 3. Использование MCP SSH
При необходимости агент может напрямую взаимодействовать с хостом через MCP-сервер `user-ssh-alttechno-bitrix` (инструмент `CallMcpTool`). Это позволяет:
*   Инспектировать файловую систему и проверять корректность доставки файлов (`execute-command`).
*   Читать логи веб-сервера и проверять PHP-конфиги на лету.
*   Диагностировать работу Bitrix без необходимости поднимать ручное SSH-соединение в терминале.
